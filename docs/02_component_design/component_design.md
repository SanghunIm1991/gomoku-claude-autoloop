# コンポーネント設計書（15×15五目並べ）

## 0. 本書の位置づけ

本書は `docs/01_requirements/requirements.md`（要件定義書、確定済み）を受けたコンポーネント設計（基本設計）工程の成果物である。システムをどのようなコンポーネント（モジュール／クラス）に分割するか、各コンポーネントの責務・扱うデータ・他コンポーネントとの関係、コンポーネント間インタフェースの概要を定義する。具体的な関数シグネチャ（引数・戻り値の型、メソッド名の確定等）は次工程の関数設計（`docs/03_function_design/`）で定める。

ID採番方針: コンポーネントIDは `COMP-01`, `COMP-02`, ... の形式で採番し、本書内で一意とする。

## 1. 全体アーキテクチャ方針

CLAUDE.md の品質方針（テスト容易性）に従い、以下の2層に明確に分離する。

- **ロジック層**: 盤面状態・手番・勝敗/引き分け判定を扱う。tkinter を含むいかなるGUIライブラリにも依存せず、単体テスト（`tests/` からロジック層を直接import して実行）が可能な純粋なPythonコードとする（NFR-05に対応）。
- **GUI層**: tkinterによる画面描画・ユーザー入力（クリック）を扱う。ロジック層のインタフェースを呼び出して着手やリスタートを依頼し、返却された結果をもとに画面表示を更新する。

依存の方向は **GUI層 → ロジック層の一方向のみ** とする。ロジック層はGUI層のいかなるコンポーネント（クラス・モジュール）も参照・importしない。これにより、ロジック層はGUI層の存在を前提とせず単体テスト可能となる。

エントリーポイント（起動処理）は上記2層とは別に1つの独立したコンポーネントとして扱う。

### 依存関係図（テキスト表現）

```
COMP-01 エントリーポイント (main.py)
  ├─ 生成 → COMP-02 ゲームロジック
  └─ 生成 → COMP-03 メインウィンドウ（GUIコントローラ）
              │  ※ COMP-03はCOMP-02のインスタンスを受け取り保持する
              ├─ 生成・保持 → COMP-04 盤面表示（BoardView）
              └─ 生成・保持 → COMP-05 ステータス表示・操作パネル（StatusPanel）

呼び出しの向き:
  COMP-03 → COMP-02   （GUIコントローラがロジック層のメソッドを呼び出す）
  COMP-04 → COMP-03   （盤面クリックをGUIコントローラへ通知する）
  COMP-05 → COMP-03   （リスタートボタン押下をGUIコントローラへ通知する）
  COMP-03 → COMP-04   （盤面の再描画を指示する）
  COMP-03 → COMP-05   （ステータス表示文言の更新を指示する）

COMP-02（ロジック層）は、GUI層コンポーネント（COMP-03/04/05）およびエントリーポイント
（COMP-01、層外）のいずれも参照・importしない。
```

## 2. コンポーネント一覧

| コンポーネントID | 名称 | 層 |
|---|---|---|
| COMP-01 | エントリーポイント | （層外）起動処理 |
| COMP-02 | ゲームロジック | ロジック層 |
| COMP-03 | メインウィンドウ（GUIコントローラ） | GUI層 |

## 3. 各コンポーネントの詳細

### COMP-01: エントリーポイント

- **責務**: アプリケーション起動処理。tkinterのルートウィンドウを生成し、COMP-02（ゲームロジック）のインスタンスを1つ生成し、それをCOMP-03（メインウィンドウ）に渡してGUI全体を構築し、tkinterのイベントループ（`mainloop`）を開始する。
- **扱うデータ**: 起動時に生成する各コンポーネントのインスタンス参照のみを一時的に保持する（永続的な状態は持たない）。
- **他コンポーネントとの関係**: COMP-02・COMP-03を生成する（起動時に1回のみ）。生成後はCOMP-03にGUI操作を委譲し、自身はイベントループの起動・維持のみを行う。
- **対応要件**: REQ-02（起動直後に空の盤面を表示する処理の起点となる）、CON-05（tkinter以外のGUIフレームワークをimportしない）、CON-06（Windows環境での起動を前提とする）、CON-07（Python 3.11環境上での起動を前提とする）。

### COMP-02: ゲームロジック

- **責務**: 15×15マスの盤面状態、現在の手番、対局状態（対局中／黒勝利／白勝利／引き分け）を保持し、以下の処理を行う。
  - 指定されたマスへの石の配置（既に石が置かれているマス、または対局が終了している状態での配置要求は、盤面状態を変更せず「無効」として扱う）
  - 石の配置直後の手番切り替え（勝敗・引き分けが確定した場合は切り替えない）
  - 石の配置直後の勝敗判定（縦・横・斜めいずれかの方向に同色の石が5個以上連続しているかの判定。ちょうど5個・6個以上のいずれも勝利と判定する）
  - 石の配置直後の引き分け判定（225マスすべてが埋まり、かつ勝利条件を満たす色が存在しない場合）
  - リスタート処理（盤面を全マス空の状態に戻し、手番を黒に戻し、対局状態を「対局中」に戻す）
- **扱うデータ**: 15×15マスそれぞれの状態（空／黒／白）、現在の手番（黒／白）、対局状態（対局中／黒勝利／白勝利／引き分け）。これらはCOMP-02が内部で完結して保持し、他コンポーネントに直接公開しない。COMP-03に対しては、4.1節に定める着手依頼・リスタート依頼の**戻り値**としてのみこれらの状態に関する情報を返し、現在の盤面・手番・対局状態を任意のタイミングで取得できる汎用の状態問い合わせ用インタフェース（getter等）は設けない。
- **他コンポーネントとの関係**: COMP-01によって1回だけ生成される。COMP-03から呼び出されるが、COMP-02自身は呼び出し元がGUIであることを一切意識しない（tkinterの型・オブジェクトを一切扱わない）。COMP-01/03/04/05のいずれもimportしない。
- **テスト容易性**: 本コンポーネントは外部ライブラリに依存しないため、`tests/` から直接importしてGUI層を介さずに単体テスト可能な構成とする（NFR-05）。
- **対応要件**: REQ-01（盤面状態の保持）、REQ-02（初期状態が全マス空であること）、REQ-04（石の配置）、REQ-05（手番切り替えとその例外条件）、REQ-06（既着手マスへの配置無効化）、REQ-07（対局終了後の配置無効化）、REQ-08（勝敗判定）、REQ-09（引き分け判定）、REQ-13（リスタートによる状態初期化）、NFR-04（判定処理自体が体感遅延を生まない軽量な実装であること）、NFR-05（GUIに依存しない単体テスト可能な構成）、CON-01（CPU機能を持たず、常に外部からの着手依頼を受け取るのみ）、CON-02（盤面サイズ15×15固定、サイズ変更機能を持たない）、CON-03（手番管理は同一プロセス内の2ユーザー交互操作を前提とし、ネットワーク通信を行わない）、CON-04（石の色は黒白2色固定、黒が先手）、CON-05（tkinter等のGUIライブラリを一切importしない）。

### COMP-03: メインウィンドウ（GUIコントローラ）

- **責務**: tkinterのメインウィンドウ（トップレベルウィジェット）を構成し、COMP-04（盤面表示）とCOMP-05（ステータス表示・操作パネル）を子ウィジェットとして配置する。GUI層全体の制御の中心として、以下を行う。
  - アプリケーション起動直後の初期表示: COMP-02の初期状態は常に「全マス空・黒番・対局中」に固定されている（COMP-01が生成した直後のCOMP-02インスタンスは必ずこの状態である）ため、COMP-03はCOMP-02への問い合わせを行わず、この固定された初期状態を前提としてCOMP-04・COMP-05に初期表示（空の盤面・黒番表示）を直接指示する。
  - COMP-04から通知された盤面クリック（行・列インデックス）を受け取り、COMP-02に石の配置を依頼する
  - COMP-02から返却された結果（配置の成否、勝敗・引き分けの確定有無、確定後の手番）をもとに、COMP-04へ石の描画更新を指示し、COMP-05へステータス表示文言の更新を指示する。ただし、返却された結果が「無効」（既に石が置かれているマスへの配置要求、または対局終了後の配置要求）であった場合は、COMP-04・COMP-05のいずれにも更新指示を行わない（表示状態を変化させない）。
  - COMP-05から通知されたリスタートボタン押下を受け取り、COMP-02にリスタートを依頼し、その結果（返却された初期状態）をもとにCOMP-04・COMP-05を初期状態表示に戻す
- **扱うデータ**: COMP-02のインスタンス参照、COMP-04・COMP-05のインスタンス参照。対局の状態そのもの（盤面・手番等）は保持せず、必ずCOMP-02への着手依頼・リスタート依頼とその戻り値（4.1節参照）を通じて取得・更新する（状態の二重管理を避ける）。
- **他コンポーネントとの関係**: COMP-01によって1回だけ生成され、生成時にCOMP-02のインスタンスを受け取る。COMP-04・COMP-05を自ら生成し保持する。COMP-02を呼び出す唯一のGUI層コンポーネントとする（COMP-04・COMP-05はCOMP-02を直接呼び出さず、必ずCOMP-03を経由する）。
- **対応要件**: REQ-02（起動直後、COMP-02への問い合わせなしに固定された初期状態を前提としてCOMP-04・COMP-05へ空の盤面・黒番表示を直接指示すること）、REQ-04（クリックからロジック層への着手依頼）、REQ-05（手番切り替え結果の表示反映）、REQ-06（無効クリック時に表示を変化させないこと）、REQ-07（対局終了後の無効クリック時に表示を変化させないこと）、REQ-10（勝敗確定時にCOMP-05へ勝利した色の表示更新を指示すること）、REQ-11（引き分け確定時にCOMP-05へ引き分け表示の更新を指示すること）、REQ-12（対局中にCOMP-05へ手番表示の更新を指示すること）、REQ-13（リスタート依頼と表示の初期化）、NFR-04（クリックから表示反映までを体感遅延なく完了させる制御）、NFR-05（GUI層からロジック層を呼び出す唯一の経路として、ロジック層への依存を一方向に保つ）、CON-03（同一ウィンドウ内で2人のユーザーの交互クリックのみを受け付け、ネットワーク通信を行わない）、CON-05（tkinterのみを用いて構成する）。

### COMP-04: 盤面表示（BoardView）

- **責務**: 15×15マスの盤面をtkinterのCanvasウィジェット上に描画する。以下を行う。
  - 起動時・リスタート時に、格子線と全マス空の状態を描画する
  - COMP-03からの指示に基づき、指定されたマスに指定色（黒／白）の石を描画する。石は格子線の交点に描画し、視認性を確保した配色（NFR-06対応）で描画する
  - ユーザーによるクリックのピクセル座標を行・列インデックスに変換し、COMP-03へ通知する
- **扱うデータ**: 盤面描画に必要な表示用パラメータ（マス目のピクセルサイズ、格子線・石の描画位置等）。対局のルール上の状態（どのマスにどちらの色があるか等）そのものは保持せず、COMP-03からの指示に基づいて描画するのみとする（状態の二重管理を避ける）。
- **他コンポーネントとの関係**: COMP-03によって生成され、COMP-03の子ウィジェットとして配置される。クリックイベントはCOMP-03へ通知するのみで、COMP-02を直接呼び出さない。
- **対応要件**: REQ-01（15×15マスの格子状盤面のGUI表示）、REQ-02（起動直後の全マス空表示）、REQ-04（クリック位置の行・列インデックスへの変換とCOMP-03への通知、および石の描画）、REQ-13（リスタート時の盤面表示クリア）、NFR-04（COMP-03からの描画指示を受けてから画面に石が反映されるまでを体感遅延なく完了させる描画処理であること）、NFR-06（石を格子線の交点に描画し、背景色・互いの色と判別可能な配色で描画することによる視認性の確保）、CON-02（盤面サイズ15×15固定の表示）、CON-04（黒・白2色の石の描画）、CON-05（tkinterのウィジェットのみで構成する）。

### COMP-05: ステータス表示・操作パネル（StatusPanel）

- **責務**: 盤面外に設けるステータス表示領域とリスタートボタンをまとめて扱う。以下を行う。
  - 対局中は現在の手番（黒／白）をテキストで表示する
  - 勝敗確定時は勝利した色をテキストで表示する
  - 引き分け確定時は引き分けである旨をテキストで表示する
  - GUI上に常設されたリスタートボタンを表示し、押下されたことをCOMP-03へ通知する
  - COMP-03からの指示に基づき、表示テキストを更新する（リスタート時は手番表示（黒番）に戻す）
- **扱うデータ**: 表示中のステータス文言（手番／勝利／引き分けのいずれを表示しているか）。対局のルール上の状態そのものは保持せず、COMP-03からの指示に基づいて表示するのみとする。
- **他コンポーネントとの関係**: COMP-03によって生成され、COMP-03の子ウィジェットとして配置される。リスタートボタンの押下通知はCOMP-03へ送るのみで、COMP-02を直接呼び出さない。
- **対応要件**: REQ-10（勝敗確定時のステータス表示）、REQ-11（引き分け確定時のステータス表示）、REQ-12（対局中の手番表示）、REQ-13（リスタートボタンの提供と、リスタート時の表示初期化）、NFR-04（COMP-03からの表示更新指示を受けてから画面のテキスト表示に反映するまでを体感遅延なく完了させる描画処理であること）、CON-04（黒・白2色に固定された色（黒番／白番、勝利した色）をテキスト表示する。ただし「石の色を黒白2色に固定し黒が先手とする」という制約自体の決定・実装はCOMP-02の責務であり、COMP-05はCOMP-03の指示に基づき決定済みの色名をテキストとして表示するのみで、色数や先手の判定ロジックは持たない）、CON-05（tkinterのウィジェットのみで構成する）。

## 4. コンポーネント間インタフェース概要

具体的な関数・メソッドのシグネチャ（引数名・型・戻り値の型）は次工程の関数設計で確定する。本書では、GUI層がロジック層をどのように呼び出し、ロジック層が何を返すかという粒度でインタフェースの概要のみを定める。

### 4.1 GUI層（COMP-03） → ロジック層（COMP-02）

- **着手依頼**: COMP-03は、盤面のマス（行・列）が指定された着手依頼をCOMP-02に対して行う。COMP-02は、その依頼が有効（空マスかつ対局中）であったか無効（既着手または対局終了後）であったかを結果として返す。有効であった場合、結果には少なくとも次の情報を含める。
  - 配置された石の色
  - この着手により勝敗が確定したか（確定した場合は勝利した色）
  - この着手により引き分けが確定したか
  - 次の手番の色（勝敗・引き分けが確定した場合は手番切り替えを行わないため、その旨が結果から判別できること）
- **リスタート依頼**: COMP-03は、対局のリスタートをCOMP-02に対して依頼する。COMP-02は、盤面・手番・対局状態を初期状態（全マス空、黒番、対局中）に戻し、その旨を結果として返す。

上記2種類（着手依頼・リスタート依頼）の戻り値のみでCOMP-03が必要とする状態情報はすべて得られるため、これとは別に現在の盤面状態・手番・対局状態を任意のタイミングで取得できる汎用の「状態問い合わせ」インタフェースは設けない。アプリケーション起動直後の初期表示についても、COMP-01が生成した直後のCOMP-02は必ず初期状態（全マス空・黒番・対局中）であることが設計上保証されているため、COMP-03はCOMP-02への問い合わせなしに初期表示を行える（3節COMP-03の責務を参照）。

### 4.2 ロジック層（COMP-02） → GUI層

ロジック層はGUI層のコンポーネントを一切呼び出さない。COMP-02はCOMP-03からの呼び出しに対する**戻り値**として結果を返すのみであり、COMP-03へのコールバック登録やCOMP-03側のオブジェクトの参照保持は行わない。これにより「GUI層 → ロジック層」の一方向依存を維持する。

### 4.3 GUI層内部（COMP-04 / COMP-05 ↔ COMP-03）

- **COMP-04 → COMP-03**: 盤面上のクリックが発生した際、クリックされたマスの行・列インデックスをCOMP-03へ通知する。
- **COMP-03 → COMP-04**: 指定したマスに指定した色の石を描画するよう指示する。リスタート時は盤面表示全体を空の状態に戻すよう指示する。
- **COMP-05 → COMP-03**: リスタートボタンが押下されたことをCOMP-03へ通知する。
- **COMP-03 → COMP-05**: 手番表示・勝敗表示・引き分け表示のいずれかのテキストへ更新するよう指示する。リスタート時は手番表示（黒番）に戻すよう指示する。
