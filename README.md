# 五目並べ（15×15 / Python + tkinter）

同一端末で人間2人が交互に着手する、15×15マスのホットシート対戦五目並べです。
CPU対戦機能は持たず、Python標準ライブラリの `tkinter` のみでGUIを実装しています。

## このプロジェクトについて

[Claude Code](https://claude.com/claude-code) を使い、要件定義からテスト・配布までをウォーターフォール形式で進めた開発実践プロジェクトです。

以前、同様の形式で作成したプロジェクト（トレーディングシミュレーター）は**工程ごとに人間が都度確認しながら段階的に**進めましたが、今回はオーケストレーター（メイン会話）が開発用・レビュー用のサブエージェントを独立に呼び出し、レビュー指摘がゼロになるまで自動で修正・再レビューを繰り返して次工程へ進める**自律ループモード**で開発しました。人間が介入したのは、工程の節目での方針確認や、再レビューが3回で収束しなかった際の判断など、要所のみです。

開発プロセスの記録（要件定義〜配布までの各工程ドキュメント、レビュー往復の記録、人間による判断・承認の記録）もあわせて `docs/` 配下にすべて残しています。

## 主な機能

- 15×15マスの盤面をGUI上に表示（起動直後は空の状態、黒石が先手）
- マス（格子線の交点）をクリックして現在の手番の色の石を配置
- 石の配置ごとに勝敗判定を実施し、縦・横・斜めいずれかの方向に同色の石が5個以上連続した時点で勝利を確定（5個ちょうどでも6個以上でも勝利）
- 全225マスが埋まり勝者がいない場合は引き分けを確定
- 盤面外のステータス表示領域に、現在の手番／勝敗／引き分けをテキストで表示
- 「リスタート」ボタンで、対局の進行状況によらずいつでも初期状態に戻せる

詳細な仕様は [`docs/01_requirements/requirements.md`](docs/01_requirements/requirements.md) を参照してください。

## 動作環境

- OS: Windows のみ
- 実行にPythonのインストールは不要（スタンドアロン実行形式で配布する場合）
- ソースから実行する場合は Python 3.11（`py -3.11` ランチャーで起動できる環境）

## 実行方法

### ソースから実行する

```
py -3.11 src\main.py
```

### スタンドアロン実行ファイル（.exe）をビルドする

`dist/`・`build/` はリポジトリに含めていないため、配布用の `.exe` は各自でビルドします。手順・トラブルシューティングは [`docs/05_distribution/distribution_manual.md`](docs/05_distribution/distribution_manual.md) に詳細を記載しています。

```
py -3.11 -m pip install pyinstaller
py -3.11 -m PyInstaller --onefile --windowed --name Gomoku --paths src src/main.py
```

生成された `dist\Gomoku.exe` をダブルクリックすると起動します。

## テストの実行

```
py -3.11 -m pytest tests\
```

ロジック層（盤面状態・手番管理・勝敗判定）はGUI描画に依存しない構成にしており、`tkinter` を介さずに単体テスト可能です。

## プロジェクト構成

```
docs/
  01_requirements/       要件定義書
  02_component_design/   コンポーネント設計書（基本設計）
  03_function_design/    関数設計書（詳細設計）
  04_test/               テスト仕様書
  05_distribution/       配布マニュアル
  traceability_matrix.md 要件〜実装〜テストのトレーサビリティマトリックス
  qa_log.md               人間による判断・承認の記録
  review_log.md            自律ループ内でのレビュー往復の記録
  handoff.md               セッション間の申し送り事項
src/                      実装コード（ロジック層とGUI層を分離）
tests/                    テストコード（pytest）
```

## 開発プロセスの記録

このリポジトリには、通常のアプリケーションコードに加えて、開発プロセス自体の記録も含まれています。

- [`docs/traceability_matrix.md`](docs/traceability_matrix.md): 要件定義書のID（REQ/NFR/CON）を起点に、コンポーネント設計・関数設計・テストまでの対応関係を追跡できるマトリックス
- [`docs/review_log.md`](docs/review_log.md): 自律ループ内でレビューサブエージェントが出した指摘と、それに対する修正の往復記録
- [`docs/qa_log.md`](docs/qa_log.md): 開発プロセスの運用ルールや配布方式など、人間が判断・承認した内容の記録
- [`docs/handoff.md`](docs/handoff.md): セッションをまたぐ際の申し送り事項
